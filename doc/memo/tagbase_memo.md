# タグベースのメモ帳の設計

https://github.com/mitoma/kashiki2/issues/80

今のメモ帳は 1 つの json ファイルで管理されておりおおよそ以下の構造を持っていた。

```json
{
    "current_category": "default",
    "categorized": {
        "category_name": {
            "created_at": "2024-06-18T12:34:56Z",
            "title": "メモのタイトル",
            "text": "メモの内容"
        }
    }
}
```

しかし、このようなメモ管理には以下の問題があった。

- カテゴリごとにメモが固定されてしまい複数のカテゴリにまたがるメモを管理しづらい
- 検索性が低く、目的のメモを見つけにくい
- 作成日時、編集日時といういった時系列に沿った管理がしづらい
- 一つの json ファイルに全てのメモが詰め込まれてしまい部分的なファイルの活用がしづらい

これらの問題を解決するために、タグベースのメモ管理を導入する。

## 要求

- メモの作成当初は日時の情報のみがあればよい
- タイトルやタグは後からつけたい
- 複数のタグを加えたい
- 無題メモを多数書きたい(scratch 的なメモにはタイトルを付けることも考えたくない)
- タグに関係なく時系列で眺められるようにしたい（emacs change-log の使い勝手が必要）
- 文字列を入力することで横断検索でメモを見つけられるようにしたい

## 設計案

- あるディレクトリをメモの場所として設定し、そのディレクトリ内のファイルレイアウトに従って管理する。

```
.gitignore
kashikishi-state.toml
kashikishi-tagbase-settings.toml
memos/
  2026-06/
    2026-06-18-001.md
    2026-06-18-002.md
    2026-06-18-003.md
    2026-06-19-001.md
  2026-07/
    2026-07-01-001.md
    2026-07-02-001.md
```

kashikishi-tagbase-settings.toml には設定情報を持たせる。

```toml
tag_definitions = ["scratch", "todo", "diary", "works", "archive"]
default_tag = "scratch"
invisible_tag = "archive"
```

kashikishi-state.toml にはユーザー個人の表示・編集状態を持たせる。
(これは個人用の設定のため、他のユーザーと共有せずに .gitignore に含めるなどして管理外とする)

```toml
# narrowing_tag は絞り込みに使用するタグのリスト。
narrowing_tag = ["todo", "scratch"]
# sort_order は一覧の既定の並び順を指定する。 "asc" または "desc" を指定可能。
sort_order = "desc"
```

このディレクトリ自体の履歴管理を Git などのバージョン管理システムで行うことでメモの変更履歴を追跡できるようにする。

これを tagbase memo としてライブラリ化し、メモの作成、編集、検索、タグ付けなどの操作を提供する。

{日付}-{連番}.md の形式でメモファイルを管理する。このメモには作成日時、更新日時、タイトル、タグ、本文などの情報を持つ必要がある。
例えば以下のように front matter を用いた形式で記述する。

```markdown
---
created_at: 2024-06-18T12:34:56Z
updated_at: 2024-06-18T12:34:56Z
title: メモのタイトル
tags: ["tag1", "tag2"]
---

メモの本文
```

### インターフェイスのイメージ

```rust
let memo_repository = TagbaseMemo::new("memos/");

// メモの作成
let memo = memo_repository.create_memo();

// メモの編集
memo_repository.update_memo(&memo, |m| {
    m.title = Some("新しいタイトル".to_string());
    m.tags.push("tag3".to_string());
});

// メモの検索
let search_results = memo_repository.search("キーワード");

// タグで絞り込み
let filtered_results = memo_repository.filter_by_tags(&["tag1"]);
```

### ディレクトリと設定の責務

- `TagbaseMemo::new(...)` に渡すパスをメモ保管庫のルートとし、その直下に設定ファイルと `memos/` を置く。
- Git に含める設定と、ユーザー個人の表示・編集状態は分ける。
  - 保管庫の設定には、ファイル形式のバージョンなど共有が必要な情報だけを保存する。
  - 現在選択中のメモや絞り込みタグなどの表示状態は、保管庫の外に保存するか、ライブラリ利用側の責任とする。
- `default_tag` は、すべてのメモに自動で付けるタグ。

### ファイル名と並び順

- ファイル名は `memos/YYYY-MM/YYYY-MM-DD-NNN.md` とする。日付は作成時のローカル日付、メタデータの日時はタイムゾーン付き RFC 3339 形式で記録する。
- 基本的にユーザーのローカルのタイムゾーン時間を用いる。
- `NNN` は同じ日の既存ファイルの最大値に 1 を足して採番する。削除などで欠番ができても詰め直さない。
- 作成日時を変更してもファイル名は変更しない。ファイル名は保管上の識別子として扱い、作成日時の代わりにはしない。
- 同時作成による同名ファイルの衝突時は、既存ファイルを上書きせず、再採番する。複数プロセスからの同時作成をどのように排他するかは考えない。基本的に kashikishi の多重起動は無いものとする。
- 一覧の既定順は作成日時の降順とし、同じ日時の場合はファイル名で安定して順序を決める。

### front matter とメモの更新

- front matter は YAML とし、`created_at` と `updated_at` はタイムゾーン付き RFC 3339 形式、`title` は省略可能な文字列、`tags` は文字列の配列とする。
- 無題のメモは `title` を省略し、タグがないメモは `tags: []` とする。本文が空でも有効なメモとして扱う。
- `created_at` は作成後に変更しない。本文・タイトル・タグのいずれかが変更された場合に `updated_at` を更新する。変更がない場合は更新しない。
- front matter を読めないファイルがあった場合、黙って無視せず、ファイルパスを含むエラーとして返す。
- 保存時は一時ファイルに書いてから置き換える方式を基本とし、書き込み途中の停止による破損を避ける。

### 検索とタグ絞り込み

- キーワード検索はタイトルと本文を対象とし、まずは大文字・小文字を区別しない部分一致とする。タグ検索はタグ絞り込みとして別の操作にする。
- タグ名の比較は完全一致とする。複数タグを指定した場合は、すべてのタグを持つメモに絞り込む（AND 条件）ことを暫定案とする。
- 検索・絞り込み結果は、特に指定がない限り作成日時の降順で返す。
- 日本語の形態素解析や高度な全文検索は初期実装の対象外とし、必要になった場合に追加する。

### API とエラー

- メモの作成・更新・削除・検索・一覧取得はライブラリの API として提供する。時系列で眺める要件を満たすため、タグに依存しない一覧取得 API も用意する。
- ファイル操作や front matter の解析に失敗する可能性があるため、作成・更新などの永続化を伴う API は `Result` を返す。
- 更新 API はメモ ID を受け取り、更新後の内容を永続化するところまでを行う。更新対象が見つからない場合や、外部編集との競合が検出された場合はエラーとして返す。
- 削除は初期案ではファイルを削除する。Git 管理を利用する場合は Git の履歴から復元できるが、Git はライブラリの必須要件とせず、ライブラリ自身は Git コマンドを実行しない。

### 既存メモからの移行

- 既存のカテゴリは、移行時に同名のタグへ変換する案を基本とする。1つのメモが複数カテゴリに属する既存データがある場合は、対応する全カテゴリをタグとして付ける。
- 既存メモの `created_at` は引き継ぎ、更新日時が存在しないため `updated_at` は移行日時を設定する。
- 移行前に元 JSON のバックアップを作成し、移行先に同内容のメモがすでにある場合は上書きせずエラーにする。
- 旧 JSON 形式の読み込み・変換を行う移行手段を用意する。移行後に旧形式を自動削除しない。

### 初期実装の範囲

tagbase_memo という crate を作成するところからスタートする。
まずはファイル保管庫、メモの作成・更新・一覧・タグ絞り込み・キーワード検索を実装する。
GUI 上の編集状態の保存、複数プロセス間の高度な同期、全文検索インデックス、Git 操作は初期実装から分離する。
